Developer Quickstart

MCP Server Integration Guide

Central Auth MCP provides centralized RS256 token issuance and RFC 7517 JWKS signature verification for Model Context Protocol servers. Connect your MCP server to enforce scoped audience boundaries and accept authorized calls from Claude, Antigravity, OpenAI/GPT, Cursor, and any custom agent without writing custom authentication logic.

1

Step 1: Register Your MCP Server

Create an identity boundary for your MCP server in Central Auth.

Navigate to the MCP Servers tab and click Register New MCP. You will define a server name and receive a unique audience identifier (aud) (e.g. mcp-invoicing). The system immediately generates both a 1-year (or permanent) static bearer token for simple setups and OAuth 2.1 credentials for dynamic clients.

2

Step 2: Choose Your Integration Mode

Select the authentication method that best fits your MCP architecture.

Mode 1 • Standards-Based

OAuth 2.1 Dynamic Flow

Full RFC 8414 metadata discovery and RFC 7636 PKCE S256 authorization code exchange.

  • check
    Supported Clients: Native integration with Claude, Antigravity, OpenAI/GPT, Cursor, and any custom agent — clients automatically negotiate tokens and refresh them.
  • check
    No manual secret copying: Tokens are issued dynamically per session and rotated seamlessly.
Mode 2 • Simplest

Static Long-Lived Token

A signed 1-year (or permanent) RS256 token passed directly in client HTTP headers (Authorization: Bearer <token> or x-api-key: <token>).

  • check
    Zero renewal burden: Issued with a 1-year default lifetime (or permanent 10-year production setting) — no manual 90-day renewal cycle.
  • check
    Zero client negotiation: Paste one token into your MCP headers or environment, done. Best for single-server setups.
  • check
    Offline verification: Your MCP verifies signatures against JWKS with zero database calls.

4

Step 4: Verify & Test

Validate your MCP server's audience protection and error handling.

check

1. Missing Token Rejection

Call your MCP endpoint without an Authorization header. Verify it immediately returns 401 Unauthorized with a WWW-Authenticate challenge.

check

2. Authorized Token Acceptance

Call with your signed static token or OAuth access token. Verify your MCP responds with 200 OK and populates the authenticated client context.

check

3. Audience Isolation Boundary

Send a token minted for a different MCP server audience. Verify your middleware strictly rejects it with 401 Invalid Audience.

check

4. Immediate Revocation Check

When a client is revoked in the admin panel, the middleware's cached revocation endpoint check invalidates both Mode 1 and Mode 2 tokens immediately.
